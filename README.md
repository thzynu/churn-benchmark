# Churn Benchmark

Leakage-safe benchmarking pipeline for bank customer churn prediction: 5 classical ML baselines (Logistic Regression, Random Forest, XGBoost, LightGBM, CatBoost) and 3 deep tabular models (MLP, TabNet, TabR), evaluated with repeated stratified cross-validation.

## Requirements

- Python 3.10–3.13
- Windows / macOS / Linux

## 1. Setup

Clone or download this repo, then from the project root:

```bash
# Create a virtual environment
python -m venv .venv

# Activate it
# Windows:
.venv\Scripts\activate
# macOS/Linux:
source .venv/bin/activate

# Install dependencies
pip install -r requirements.txt
```

> Note: `torch` and `pytorch-tabnet` are required only for the deep models (MLP/TabNet/TabR). If you don't need them, skip installing those two lines from `requirements.txt` and run with `--skip-deep` (see below). `optuna` is required only for `tune_deep_models.py`.

## 2. Data

Make sure `data/churn.csv` exists (already included in this repo). The pipeline reads it via the path set in `config.py`.

## 3. Run the full pipeline

From the project root:

```bash
python main.py
```

This runs, in order:
1. Leakage audit on the raw dataset
2. Hyperparameter tuning + repeated CV for the 5 classical baselines
3. Repeated CV for the 3 deep models (MLP, TabNet, TabR)
4. Statistical significance tests (Friedman + pairwise Wilcoxon)
5. Imbalance-handling ablation (none / class weighting / SMOTE)
6. SHAP feature-importance analysis for every model

All tables are written to `outputs/tables/*.csv` and all figures to `outputs/figures/*.png`.

### Useful flags

```bash
# Quick smoke test (1 seed, small hyperparameter search, fewer epochs)
# — use this first to confirm everything runs before the full multi-hour run
python main.py --quick

# Skip the deep models (useful if torch / pytorch-tabnet aren't installed)
python main.py --skip-deep
```

Full run time depends on hardware; expect it to take from tens of minutes to a few hours on a laptop CPU due to hyperparameter search and repeated CV.

## 4. Leakage demonstration (optional, standalone)

To reproduce the before/after data-leakage comparison on its own (without running the whole pipeline):

```bash
python leakage_demo.py
```

This writes `outputs/tables/leakage_before_after.csv`.

## 5. Generate manuscript figures

After `main.py` has completed at least once (it needs the CSV results it produces), generate every remaining figure needed for the manuscript:

```bash
python generate_figures.py
```

This reads the existing CSVs in `outputs/tables/` (no need to re-run the full CV) and produces, numbered to match the manuscript:

- `fig2_smote_distribution.png` — Fig. 2: class distribution before/after SMOTE
- `fig3_confusion_matrices.png` — Fig. 3: aggregated confusion matrices for all 8 models
- `fig4_calibration_curves.png` — Fig. 4: reliability diagram (calibration) for all models
- `fig5_computational_efficiency.png` — Fig. 5: training time and inference latency per model
- `fig6_shap_all_models.png` — Fig. 6: SHAP feature-importance grid for all 8 models
- `fig7_correlation_heatmap.png` — Fig. 7: feature correlation heatmap (multicollinearity check via VIF/Cramér's V) preceding SHAP interpretation
- `fig8_numofproducts_vs_exited.png` — Fig. 8: churn rate by number of products held
- `fig9_shap_waterfall.png` — Fig. 9: local SHAP explanation for a retained and a churned customer

It also writes `outputs/tables/table_computational_efficiency.csv`.

A few of these figures (Fig. 4, Fig. 9) refit a single quick model rather than reading purely from CSVs, so this step takes a couple of minutes, not hours.

> Note: two manuscript figures cannot be generated by code and must be produced manually — Fig. 1, the architecture diagram, and Fig. 9, the web-application screenshots (if that section is kept).

## 6. Round-2 analysis scripts (advisor's second review)

These extend the pipeline to address the advisor's follow-up review (research depth: effect sizes, multicollinearity, fairness, robustness, tuned deep models). They are additive — none of them modify `main.py`, `src/`, or previously generated results. Run `main.py` at least once first.

```bash
python multicollinearity_check.py   # VIF + correlation matrix + Cramer's V (~5s)
python effect_size.py               # Cliff's Delta + Kendall's W (~1s, reads existing CV results)
python shap_stability_extra.py      # Kendall's Tau across models (~1s, reads existing SHAP results)
python fairness_analysis.py         # Subgroup metrics by Gender / Geography (~10s)
python robustness_analysis.py       # Leave-one-country-out, missing features, noise (~1-2 min)
python efficiency_extra.py          # Peak RAM + serialized model size (~1-2 min)
python tune_deep_models.py          # Optuna tuning for MLP/TabR/TabNet (30-90 min — see below)
```

Each writes its own CSV(s) to `outputs/tables/`. See `NEW_ANALYSES_README.md` for the full mapping between each script and the specific review point it addresses, plus important notes on `tune_deep_models.py` (run `--quick` first; TabNet uses a reduced trial budget due to its high and variable training cost).

## Troubleshooting

- **`ImportError` for `torch` or `pytorch_tabnet`**: install them (`pip install torch pytorch-tabnet`) or run with `--skip-deep`.
- **`ImportError` for `optuna`**: only needed for `tune_deep_models.py` — install with `pip install optuna`.
- **Long runtime**: use `python main.py --quick` first to validate the setup before committing to a full run. Same idea applies to `tune_deep_models.py --quick`.
